# Website tag (any site builder)

One script tag translates any public website in the visitor's browser: Wix, Squarespace, Bubble, Carrd, Jimdo, Weebly, Duda, sites generated by Lovable, Bolt or Base44, or plain HTML. It shows a language switcher, applies your glot translation memory, and sends new public text to glot so it gets translated. You don't need DNS changes, a proxy or any code beyond the tag itself.

```html
<script src="https://app.glotlang.com/widget/glot.js" data-project="your-project" data-key="pk_…" async></script>
```

Copy the exact tag (with your public key) from **glot Edge → Website tag** in the dashboard, then turn the tag **on** there. Until it's on, the tag does nothing.

> **Note:** Text translated in the browser is not reliably indexed by search engines. For pages you want found in other languages, add the [SEO subdomain mode](#seo-subdomain-mode) too. It takes one CNAME.

## Where to paste it

Paste the tag once, site-wide, in the page `<head>`:

| Platform | Where | Plan / requirement |
|---|---|---|
| Wix / Wix Studio | Dashboard → Settings → Custom Code → + Add Custom Code → All pages, **Head** | The site must be published with a connected domain ([Wix](https://support.wix.com/en/article/embedding-custom-code-on-your-site)) |
| Squarespace | Settings → Developer tools → Code Injection → **Header** | Core, Plus, Advanced and some legacy plans ([Squarespace](https://support.squarespace.com/hc/en-us/articles/205815908-Using-code-injection)) |
| Bubble | Settings → SEO / metatags → Script/meta tags in header | ([Bubble manual](https://manual.bubble.io/help-guides/maintaining-an-application/seo/seo-app)) |
| Carrd | Add an **Embed** element: Type = Code, Style = Hidden, location **Head** | Pro Standard or higher ([Carrd](https://carrd.com/docs/building/embedding-custom-code)) |
| Weebly | Settings → SEO → Header Code | Paid plans only, according to vendor guides. Weebly's own help center doesn't confirm the tier. |
| Jimdo | Creator: Settings → Edit Head. Dolphin: custom HTML on Business plans and up | Not on the free plan, according to vendor guides. Check your dashboard. |
| Duda | Site settings → Head HTML, or Developer Mode `header.html` | Paths from vendor guides. Duda's help article requires sign-in. |
| Lovable, Bolt, Base44, any code export | Add the tag to `index.html` (or the root layout) before `</head>` | You need to be able to edit the generated code |

If your plan has no custom code, the tag can't be installed there. Use the [SEO subdomain mode](#seo-subdomain-mode) instead, as long as you can add a CNAME to your domain.

## What the tag does

- **Language**: it uses `?lang=es` if present, then the visitor's saved choice (`localStorage`), then the browser language. It sets `<html lang dir>` to match.
- **Translation in place**: the tag applies your translation memory to the text, `<title>` and meta description. It uses the same segmenter and hashes as glot Edge, so a text translated once is translated everywhere. Switching languages from the source needs no reload. Going back to the source reloads the page.
- **SPA navigation**: text the site renders later (route changes through `history.pushState`, late content) is translated as it appears.
- **Never blocks rendering**: the tag loads `async`. If glot can't be reached, the page stays as published. The last good status, language list and translation memory are kept locally.
- **Off switch**: turn the tag off in the dashboard and visitors see your original site again on their next page view.

## Switcher

The tag shows the `<glot-locale-switcher>` menu in the position set in the dashboard: a floating corner, **hidden** (for your own switcher), or inside an element (a CSS selector such as `#SITE_HEADER nav`). If the element is rendered later, the switcher is placed as soon as it appears. An element marked `data-glot-switcher` always receives the switcher.

You can also change these on the tag itself:

| Attribute | |
|---|---|
| `data-position` | `bottom-right`, `bottom-left`, `top-right`, `top-left`, `none`, or a CSS selector |
| `data-switcher="none"` | No switcher. Call `glot.setLocale("es")` from your own controls. |
| `data-server` | glot API for self-hosted servers (default: `api.` + the host the script is served from) |

The languages offered are your project's target languages, or the subset you check in the dashboard.

## New text and privacy

When a visitor views a page in another language, text that's missing from the translation memory is reported to glot (`POST /edge/v1/{project}/missing`, `mode: "website"`). Depending on the **Translate new text automatically** setting, it is either translated automatically or held in the review queue. What is never sent:

- personal data (emails, phone numbers, card numbers, IBANs, street addresses, long numbers): masked or skipped by the tag, and checked again by the server;
- anything inside a form except its labels, legends and buttons, and never what visitors type;
- text in `translate="no"`, `.notranslate`, `[data-glot-skip]`, `[data-glot-user]`, editable areas or the project's excluded selectors;
- anything at all when the visitor has a session cookie (signed-in members);
- query strings (only the path is sent), cookies, or the visitor's identity. glot requests are sent without credentials.

The `data-key` is public. All it lets a page do is report text to translate, within your discovery zones and daily cap.

## SEO subdomain mode

Google indexes the HTML your server sends. For indexable translated pages, add a glot Edge subdomain (`es.your-site.com CNAME edge.glotlang.com`; see [glot Edge](/docs/edge)). Each language is then served as translated HTML with canonical and hreflang tags. Once a subdomain is verified and its language is SEO-ready:

- the switcher sends visitors to the subdomain (e.g. `https://es.your-site.com/pricing`) instead of translating in the browser;
- on your source site, the tag adds the `<link rel="alternate" hreflang>` tags in the browser and keeps them in sync on SPA navigation;
- search engines should also find those tags in your HTML. Copy them from **Website tag → Search engines** in the dashboard and paste them into your site's head (custom code). If you paste them, the tag leaves them alone.

Pages served by glot Edge are left to the Edge: on those pages the tag only shows the switcher.

## Limits

- The first visitor in a new language may see the source text for a few seconds until the new text is translated (the tag fetches the translation memory again after 30 s, 2 min and 10 min).
- Some sites set their session cookie as `HttpOnly`, which the tag can't see. On builders with member areas, exclude those paths in **Settings → Discovery** (for example `/account/*`).
- Platforms that don't allow custom code on your plan can't run the tag.
